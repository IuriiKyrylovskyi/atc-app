# How to upload paid backgrounds

Quick reference for `pnpm upload:paid-backgrounds` — what it does, and when
you actually need to run it.

## What it does

Uploads everything in `./dist_remote_assets/backgrounds/` (generated by
`pnpm build:levels`) to the private `game_assets` Supabase Storage bucket,
under a `backgrounds/` prefix. That's every ratio × dpr × format variant for
every **paid** level (`levelNumber > freeLevelLimit` in
`process-backgrounds.config.json`), plus `manifest-paid.json` — uploaded last
on purpose, so the app never sees a manifest entry pointing at a file that
hasn't finished uploading yet.

It does **not** touch free levels — those are bundled straight into the app
by `pnpm build:levels` writing into `packages/app/src/assets/backgrounds/`,
which ships automatically on the next `pnpm build`. No upload step, no
Supabase involved, for free levels ever.

## When you need to run it

Run `pnpm upload:paid-backgrounds` (after `pnpm build:levels`) any time:

- **You add a new paid level** — new `raw_assets/level-N-master.png` where
  `N > freeLevelLimit`.
- **You re-export or resize an existing paid level's master image** — e.g.
  fixing one of the too-small masters, or repainting art.
- **You change background-generation config** in
  `process-backgrounds.config.json` in a way that affects paid levels —
  `mobileZoom`, `mobileRatios`, `dprBuckets`, `formats`, `fallbackFormat`,
  `fallbackDprBuckets`, `webpQuality`.
- **A level crosses the free/paid boundary** — you change `freeLevelLimit`,
  or renumber levels (like the level 3/4/5/6 reshuffle earlier), and a
  level's routing (bundled vs remote) changes as a result.
- **You add or change a runway's `masterX`/`masterY`/`masterLength`/
  `direction`** — wait, actually **no** — runway position data lives in
  `levels.config.ts`, not in the background manifest. Changing runway data
  alone never requires a re-upload. Only the _image files themselves_
  changing requires it.

You do **not** need to run it just because you edited `levels.config.ts`,
`levels_full.json` (that's `upload:paid-levels`, a different script — see
below), or any app code. Only background _image_ changes for _paid_ levels.

## The two-step order matters

```bash
pnpm build:levels              # 1. regenerates dist_remote_assets/backgrounds/
                                #    + manifest-paid.json from raw_assets/
pnpm upload:paid-backgrounds   # 2. pushes that output to Supabase Storage
```

Running the upload without a fresh `build:levels` first just re-uploads
whatever was already generated — harmless, but pointless if you changed a
master image and forgot to rebuild first. If you're not sure whether
`dist_remote_assets/backgrounds/` is current, just run `build:levels` again;
it's fast and idempotent (only touched files change).

## Credentials

Needs `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (the **service_role**
secret key from Supabase dashboard → Project Settings → API — not the anon
key). This is a build-time/CI-only command; never put these values in a
committed file or run this from the app itself.

```bash
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=eyJ... \
pnpm upload:paid-backgrounds
```

## Sibling command: `upload:paid-levels`

Same idea, different content — `pnpm upload:paid-levels` uploads
`./content/levels_full.json` (level _parameters_: runways, waypoints, spawn
rates) to the same bucket, as `levels_full.json` at the bucket root. Run that
one when you change level data, not background images. The two are
independent — changing one never requires running the other.

## Verifying it worked

- **Supabase dashboard**: Storage → `game_assets` → `backgrounds/` — should
  show one folder per ratio (`16x9/`, `20x9/`, …) plus `manifest-paid.json`.
- **Access control** (do this once after any bucket/RLS change, not every
  upload):
  ```bash
  curl -H "Authorization: Bearer <a free user's JWT>" \
    "https://YOUR_PROJECT_REF.supabase.co/storage/v1/object/game_assets/backgrounds/manifest-paid.json"
  ```
  Should return `403`. If it doesn't, stop — the RLS policy isn't applied
  correctly, fix that before anything paid goes live.
- **In the app**: as a premium test user, enter a paid level and confirm the
  background loads (check `backgroundAssetService.ts`'s console logs, or the
  in-game debug overlay's `bg loaded` / `bg size` lines).

## What happens if you forget

Nothing breaks immediately — the app falls back to whatever's already in the
bucket (stale art, or nothing if this is a brand-new paid level, which just
means that level's background never loads for anyone until you upload it).
Nothing leaks; a forgotten upload is a content bug, not a security issue.
