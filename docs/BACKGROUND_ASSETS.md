# Background asset pipeline — remote-asset workflow

This documents the contract between `scripts/process-backgrounds.ts` (build time)
and the runtime asset service (app side). Anything that reads or writes level
background images should conform to this doc, not to ad-hoc string building.

## 1. Naming convention

```
<ratio-folder>/<level>@<dpr>x.<ext>          (preferred format, every dpr bucket)
<ratio-folder>/<level>.<ext>                 (1x fallback format only — bare name, no @1x)
```

Ratio is **already** the folder name — it is not repeated in the filename.
The 1x fallback keeps the exact bare `<level>.<ext>` name that was already in
this repo before this pipeline existed (e.g. `16x9/level-4.png`), so the
already-generated levels 1–7 aren't renamed or orphaned. Every other
(format, dpr) combination gets an explicit `@<dpr>x` suffix — this already
matched the pre-existing `level-4@2x.webp` files at 2x.

- `level` — canonical level name, currently `level-<n>` (e.g. `level-4`). Derived
  from the source filename with `-master` / `-source` / `-main` suffixes stripped.
- `ratio-folder` — one of `16x9`, `20x9`, `19_5x9`, `16x10`.
- `dpr` — device-pixel-ratio bucket, currently `1` or `2`.
- `ext` — `webp` (preferred) or `png` (fallback, 1x only by default).

Examples:

```
16x9/level-4.png            (1x, fallback format — pre-existing bare name)
16x9/level-4@1x.webp        (1x, preferred format — new)
16x9/level-4@2x.webp        (2x, preferred format — pre-existing)
20x9/level-4@1x.webp
```

Files live under `packages/app/src/assets/backgrounds/<ratio>/` (free) or
`dist_remote_assets/backgrounds/<ratio>/` (paid, not bundled — see §2).

## 2. Manifests — split by free vs. paid (buckets, not bundling)

**Neither tier's image binaries ship in the app anymore.** Bundling every
ratio × dpr × format combination for every free level — when a single
device only ever uses one — was pure app-size waste, worse on mobile where
install size affects conversion. Both tiers download on demand and cache
locally; the only difference is which bucket (public vs. private+RLS).

There are still **two** manifests, generated by the same build script,
routed by `freeLevelLimit` in `process-backgrounds.config.json` (must match
`FREE_LEVEL_LIMIT` in `packages/app/src/stores/monetization.ts`):

|                              | Free levels (`levelNumber <= freeLevelLimit`)                                                                                 | Paid levels (`levelNumber > freeLevelLimit`)                                                     |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Image binaries written to    | `dist_remote_assets/backgrounds-public/`                                                                                      | `dist_remote_assets/backgrounds-private/` (both outside `packages/app/src` — neither is bundled) |
| Manifest written to          | `dist_remote_assets/backgrounds-public/manifest.json`, **also copied to** `packages/app/src/assets/backgrounds/manifest.json` | `dist_remote_assets/backgrounds-private/manifest-paid.json` only                                 |
| Manifest ships in app bundle | Yes (tiny JSON, negligible — just structure, not images)                                                                      | No                                                                                               |
| Uploaded to Supabase         | `pnpm upload:free-backgrounds` → `game_assets_public` bucket (public, no auth)                                                | `pnpm upload:paid-backgrounds` → `game_assets` bucket (private, RLS)                             |
| Read at runtime by           | `backgroundAssetService.ts` (`getBackgroundForLevel`) — same function as paid, decides bucket internally                      | same                                                                                             |

A level whose name doesn't match `level-<n>` (no parseable number) defaults
to the **free/public** tier — an unparseable name should never accidentally
route paid content into the public bucket.

Re-running the build script for one level/ratio only updates the entries that
changed within its manifest — existing entries for other levels are preserved
(merge key is `level + ratio + dpr + format`).

Shape (identical for both manifests):

```json
{
  "generatedAt": 1737100000000,
  "scriptVersion": "0.0.80",
  "entries": [
    {
      "level": "level-4",
      "levelNumber": 4,
      "ratio": "16x9",
      "dpr": 1,
      "format": "webp",
      "isFallback": false,
      "file": "level-4@1x.webp",
      "path": "16x9/level-4@1x.webp",
      "width": 1920,
      "height": 1080,
      "size": 184320,
      "checksum": "sha256 hex",
      "zoom": 1,
      "crop": { "left": 0, "top": 0, "width": 3840, "height": 2160 },
      "sourceFile": "raw_assets/level-4-master.png",
      "generatedAt": 1737100000000,
      "scriptVersion": "0.0.80"
    }
  ]
}
```

- `path` is what you fetch/cache the asset by, relative to the bucket's
  `backgrounds/` prefix.
- `checksum` (sha256) validates a downloaded file before caching it and
  detects a stale cache entry after a content update.
- Only the single resolved asset for the current device should ever be
  downloaded — never the whole tree — for either tier.

## 3. Runtime variant-selection algorithm

Run once at startup (device characteristics don't change mid-session):

1. Read `window.devicePixelRatio` (or platform equivalent) → round to nearest
   available `dprBuckets` value, clamped to the manifest's min/max.
2. Compute the device's aspect ratio (`screenW / screenH`) → pick the closest
   available `ratio` key by numeric aspect distance, not string matching.
3. Filter manifest entries for `(level, ratio, dpr)`.
4. Prefer entries in `formats` priority order (currently `webp` first); use
   `isFallback` entries only if the preferred format is unsupported or fails
   to load/decode.
5. If no entry exists for the exact `(ratio, dpr)` pair, fall back in this
   order: same ratio + lower dpr → next-closest ratio at the requested dpr →
   next-closest ratio + lower dpr → the `16x9` @ `1x` webp entry (baseline,
   always generated) as the last resort.

This selection should happen **once per app session**, producing a single
resolved `path` per level, not per frame/render.

## 4. Free vs. paid content

|                                     | Free levels                                                                                  | Paid levels                                                                                                                                |
| ----------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Level parameters (JSON)             | bundled in app                                                                               | fetched after entitlement confirmed                                                                                                        |
| Manifest                            | bundled (`manifest.json`, small JSON only)                                                   | fetched from `game_assets/backgrounds/manifest-paid.json` after entitlement confirmed                                                      |
| Background asset (the actual image) | downloaded on demand from `game_assets_public/backgrounds/<path>`, one variant only, no auth | downloaded on demand from `game_assets/backgrounds/<path>`, one variant only, after access check                                           |
| Network required                    | yes, until cached (even on first launch)                                                     | yes, until cached                                                                                                                          |
| Access control                      | none needed — `game_assets_public` is a public bucket, nothing sensitive lives there         | `game_assets` bucket RLS: `is_premium = true` — covers the JSON **and** every background binary, since both live in the same bucket/prefix |

Paid-level flow, in order, only after purchase/entitlement is confirmed:

1. Download full paid levels JSON.
2. Resolve + download the current level's single best-matching asset (per §3).
3. Prefetch the next unlocked level's asset in the background (non-blocking,
   should not delay gameplay).

Never issue a download for a paid asset before entitlement is confirmed —
this includes prefetching. Free levels have no such gate — `BootScene.ts`
preloads the current free level's background at boot; paid levels are always
deferred to `GameScene`'s access-checked path regardless of what level a
resumed session lands on (see `BootScene.ts`'s own header for the specific
guard against a resumed-on-a-paid-level edge case).

## 5. Caching

- Cache key = bucket + manifest `path` (checksummed on every read, so a
  content update — same path, different bytes — is detected automatically
  rather than needing a separate cache-busting scheme).
- On cache hit with matching checksum, skip network entirely and load from
  local storage / Phaser texture cache.
- On checksum mismatch (asset updated), re-download and replace the cache
  entry.
- Neither tier hits the network in steady state once cached — including free
  levels now, which only need network on first download, not every launch.
- Native (Capacitor): Filesystem, base64 → `data:` URI. Web/Electron:
  IndexedDB → object URL (not the Cache Storage API — that requires a secure
  context, https/wss/localhost, which Electron's `file://` app load doesn't
  reliably provide; IndexedDB has no such restriction).

## 6. What the build script does (`process-backgrounds.ts`)

- Generates every `(ratio, dpr, format)` combination per config, using the
  existing deterministic center-crop + zoom logic (unchanged aspect-ratio and
  focal-point math — only the buckets/formats generated changed).
- Routes free levels to `dist_remote_assets/backgrounds-public/` and paid to
  `dist_remote_assets/backgrounds-private/` — **neither** writes image
  binaries into `packages/app/src` anymore. Free levels additionally get
  their manifest copied to `packages/app/src/assets/backgrounds/manifest.json`
  (the bundled structure-only copy — see §2).
- Fallback format + which DPR buckets get it are configurable in
  `process-backgrounds.config.json` (`fallbackFormat`, `fallbackDprBuckets`) —
  defaults to PNG at 1x only, to avoid doubling build output/size for the 2x
  tier where WebP support is effectively universal.
- Warns (doesn't block) if a master image is smaller than
  `expectedMasterWidth`/`expectedMasterHeight` — see "Master image spec" in
  `LevelBackgrounds.md`.

## 7. Runtime pieces (implemented)

- `backgroundVariantResolver.ts` — shared selection algorithm (§3), used for
  both tiers so they never diverge.
- `backgroundAssetService.ts` — the single loader for every level, free and
  paid alike. `getBackgroundForLevel(n)` picks the bucket internally based on
  `FREE_LEVEL_LIMIT`; callers don't branch. Resolves, downloads,
  checksum-verifies, and caches. Native caching via Capacitor Filesystem
  (base64 → `data:` URI); web/Electron via IndexedDB → object URL (not the
  Cache Storage API — see §5 for why).
- `assetLoader.ts` — now only owns plane sprites (still bundled — unrelated
  to this change) plus a thin `loadBackgroundImages()` wrapper around
  `backgroundAssetService` for `BootScene`'s call shape.
- `GameScene.ts` — background loading collapsed to one call
  (`getBackgroundForLevel()`) for every level; the free/paid branching that
  used to live here moved inside the service. `backgroundMetadata` (the crop
  rect used by `projectMasterToWorld`) now comes directly from the resolved
  asset's manifest entry instead of a separate lookup.
- `monetization.ts` — `hydratePaidContent()` (paid JSON → current level bg →
  next unlocked level's background prefetch) unchanged in shape, now calls
  the unified service functions directly.
- `BootScene.ts` — preloads the current level's background **only if it's
  free** (`targetLevel <= FREE_LEVEL_LIMIT`) — a resumed session on a paid
  level must never trigger an unauthenticated download attempt at boot;
  `GameScene`'s access-checked path handles that case instead.

## 8. One-time setup and migration

- **`game_assets_public` bucket** (new — you need to create this): Supabase
  dashboard → Storage → New bucket → name it `game_assets_public` → toggle
  "Public bucket" on. No RLS policy needed. Then run
  `pnpm build:levels && pnpm upload:free-backgrounds` to populate it.
- **`game_assets` bucket** (existing, private): unchanged — see
  `PAID_BACKGROUND_MIGRATION.md` for the original one-time migration off the
  old public `level-backgrounds` bucket, and `pnpm upload:paid-backgrounds`
  for ongoing paid-content updates.
